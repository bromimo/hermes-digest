# Примеры прогонов дайджеста

Два реальных последовательных прогона навыка `news-digest` моделью `openai/gpt-oss-120b:free`
(OpenRouter) в режиме Hermes CLI one-shot (`hermes -z "..."`), без Telegram:

```
docker compose run --rm hermes-agent -z "собери дайджест по теме AI/ML за последнюю неделю"
```

Через Telegram дайджест собирается тем же способом (запрос → Hermes → те же MCP-инструменты →
ответ в чат); воспроизводится `docker compose up` после настройки `.env`. Сырые логи прогонов —
в `.log/` (в git не коммитятся).

В самих `.md` под маркером — **дословный вывод модели** (verbatim); метаданные и разбор — ниже.

## Прогоны (дедуп работает)

Состояние дедупа хранит **сервер MCP** (SQLite по ключу `digest:ai-ml`), память Hermes не
используется — см. ADR `../decisions/0001-deterministic-dedup.md`.

| Файл | № | Стор `digest:ai-ml` на входе | Показанные статьи |
|---|---|---|---|
| `2026_06_14_223531_digest_ai_ml_7d.md` | 1 | пусто (после `docker compose down -v`) | `1047288, 1047286, 1047022, 1046918, 1046568` |
| `2026_06_14_224300_digest_ai_ml_7d.md` | 2 | 5 ID прогона 1 | `1047038, 1046890, 1046996, 1046409, 1046610, 1046497, 1046489` |

**Пересечение прогона 2 с прогоном 1 — ноль.** `dedup_filter` прочитал серверный стор по `key` и
исключил все статьи прогона 1; модель показала 7 полностью новых. После прогона 2 стор содержит
объединение (12 ID): `1047288, 1047286, 1047022, 1046918, 1046568, 1047038, 1046890, 1046996,
1046409, 1046610, 1046497, 1046489`.

## Как работает дедуп (L3)

- **Состояние — на стороне MCP** (SQLite в volume `mcpnews-data`), ключ `digest:<chat_id>:<тема-slug>`
  (в CLI без chat_id — `digest:<тема-slug>`).
- `dedup_filter(key, candidates)` сам читает стор и убирает показанное; `dedup_commit(key, shown_ids)`
  атомарно дописывает показанные ID (объединение + скользящее окно `keep=50`). Модель передаёт
  **только `key`** — ничего не читает/пишет в память Hermes.
- Почему не память Hermes: её инструмент `memory` не умеет читать (только add/replace/remove), и
  модель не может получить прежний список — подробности и трейс в ADR (раздел «Дополнение»).
- **Гонки решены** атомарной транзакцией на стороне сервера.

## Именование

Файлы дайджестов — в стиле миграций Laravel: `YYYY_MM_DD_HHMMSS_<тема>_<период>.md`
(timestamp = время прогона → хронологическая сортировка); обложка рядом в `img/` под тем же
именем с суффиксом `_cover.png`.

# Примеры прогонов дайджеста

Два реальных прогона навыка `news-digest` моделью `openai/gpt-oss-120b:free` (OpenRouter) в
режиме Hermes CLI one-shot (`hermes -z "..."`), без Telegram:

```
docker compose run --rm hermes-agent -z "собери дайджест по теме AI/ML за последнюю неделю"
```

Через Telegram дайджест собирается тем же способом (запрос → Hermes → те же MCP-инструменты →
ответ в чат); воспроизводится `docker compose up` после настройки `.env`. Сырые логи прогонов
лежат в `.log/` (в git не коммитятся).

В самих `.md` под маркером — **дословный вывод модели** (verbatim); метаданные и разбор — ниже.

## Прогоны

| Файл | № | Память на входе | Итог |
|---|---|---|---|
| `2026_06_14_191924_digest_ai_ml_7d.md` | 1 | пусто (после `docker compose down -v`) | 4 статьи; агент вызвал `dedup_filter`/`dedup_commit` и записал `digest:ai-ml ids: 1047288, 1047286, 1047022, 1046918` |
| `2026_06_14_202202_digest_ai_ml_7d.md` | 2 | строка прогона 1 | 7 статей, из них **4 — повтор** прогона 1 (дедуп не применился) |

## Дедупликация (L3) — что показали прогоны

- **Код дедупа детерминирован и работает:** прогон 1 отфильтровал кандидатов и записал в память
  Hermes строку `digest:ai-ml ids: 1047288, 1047286, 1047022, 1046918`.
- **Оркестрация на free-модели стохастична:** прогон 2 (та же тема и модель) дедуп **не
  задействовал** — память на вход `dedup_filter` не подал и `dedup_commit` не вызвал (строка
  памяти не изменилась), поэтому повторил 4 статьи прогона 1 и добавил 3 новые
  (`1043848, 1046698, 1046383`).
- Это ровно оговорка из ADR `../decisions/0001-deterministic-dedup.md` и README → «Известные
  оговорки»: механика дедупа в коде MCP надёжна, а *вызов* инструментов слабой моделью — нет.
  Для стабильного дедупа — более сильная модель через `HERMES_MODEL`.

## Именование

Файлы дайджестов — в стиле миграций Laravel: `YYYY_MM_DD_HHMMSS_<тема>_<период>.md`
(timestamp = время прогона → хронологическая сортировка); обложка рядом в `img/` под тем же
именем с суффиксом `_cover.png`.

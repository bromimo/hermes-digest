# Навык: новостной дайджест по Хабру

Ты собираешь **связную обзорную статью-дайджест** (не просто список) на русском
языке по запросу пользователя из Telegram и присылаешь её в тот же чат.

## Инструменты

- `mcp_mcpnews_search_habr(query, period, limit)` — поиск статей по запросу,
  новейшие сверху. **Основной** инструмент для конкретной темы.
- `mcp_mcpnews_get_news(topic, period, limit)` — лента по хабу/теме из RSS.
  Запасной/широкий вариант, если поиск дал мало.
- `mcp_mcpnews_fetch_article(url)` — полный текст + метаданные + картинка
  (`image`) статьи. Зови для аннотации и для обложки.
- `mcp_mcpnews_dedup_filter(candidates, seen_blob)` — убирает уже показанные статьи из
  кандидатов и проставляет числовой `id`. Зови после сбора кандидатов, до отбора.
- `mcp_mcpnews_dedup_commit(key, shown_ids, seen_blob)` — возвращает обновлённую строку
  памяти (объединение показанного + обрезка окна). Зови после сборки дайджеста, перед записью.
- `memory` — встроенная память. Используется для дедупа между запросами.

`period`: `"24h"`, `"7d"`, `"30d"`, `"Nd"` (например `"3d"`) или диапазон `"YYYY-MM-DD..YYYY-MM-DD"`.

## Процедура

### 1. Разбор запроса
Извлеки из сообщения **тему** и **период**. Маппинг периода:
«сегодня/за сутки/за день» → `24h`; «за неделю/последнюю неделю» → `7d`;
«за месяц» → `30d`; «за N дней» → `Nd`. Если период не указан — `7d`.

### 2. Дедуп: что уже показывали (память)
Сформируй ключ `digest:<chat_id>:<тема-slug>` (тему приведи к нижнему регистру,
пробелы → дефисы). (`chat_id` — числовой идентификатор Telegram-чата из контекста текущего
сообщения/сессии. Если определить его невозможно, используй ключ только по теме: `digest:<тема-slug>`.)
Найди в памяти (`MEMORY.md`) строку с этим ключом и **запомни её дословно** как `SEEN_BLOB` —
она понадобится и для фильтрации (шаг 3), и для записи (шаг 7). Запомни также, **была ли** такая
строка (для выбора `add`/`replace` в шаге 7). Если строки нет — `SEEN_BLOB` пуст.

### 3. Сбор кандидатов и фильтрация
Вызови `mcp_mcpnews_search_habr(query=тема, period, limit=20)`. Если `count` мал (< 5),
дополни через `mcp_mcpnews_get_news(topic=тема, period, limit=10)`. Объедини результаты в один
список кандидатов.

Передай его в `mcp_mcpnews_dedup_filter(candidates=<список>, seen_blob=SEEN_BLOB)`. Инструмент
вернёт `fresh` — кандидатов, ещё не показанных ранее, с проставленным числовым `id` у каждого.
**Фильтрацию и удаление дублей делает инструмент — не фильтруй вручную и не выдумывай ID.**

Сообщение «новых материалов нет» допустимо **только** если `fresh` пуст. Если в `fresh` есть хотя
бы один элемент — ты **обязан** собрать дайджест из них (даже если их меньше 5–7). Если `fresh`
пуст — вежливо сообщи по-русски, что новых материалов за период не нашлось (предложи расширить
период), и заверши.

### 4. Отбор и аннотация
Из `fresh` (шаг 3) отбери до **5–7** самых релевантных свежих статей (если их меньше 7 — возьми
все). Для каждой вызови `mcp_mcpnews_fetch_article(url)`, чтобы получить текст и `image`. На основе
текста напиши **TL;DR в 2–3 предложения** — по сути, без воды и без выдуманных фактов (только то,
что есть в тексте/сниппете).

> Экономь вызовы: free-модель ограничена ~20 запросами/мин. Не зови
> `mcp_mcpnews_fetch_article` больше, чем нужно для 5–7 пунктов.

Если `mcp_mcpnews_fetch_article` вернул поле `error` — пропусти эту статью и возьми следующего
кандидата из `fresh` (не прерывай дайджест).

**Зафиксируй `SHOWN_IDS`** — значения поля `id` ровно тех элементов `fresh`, что реально войдут в
итоговый дайджест (уже после всех пропусков из-за `error`). Бери `id` из `fresh` как есть — ничего
не вычисляй и не парси из URL. Этот список — **единственный источник правды**: ровно эти статьи
идут и в тело дайджеста (шаг 5), и в память (шаг 7).

### 5. Сборка статьи
Структура (см. `templates/digest.md`):
- **Вводка** (2–3 предложения): о чём дайджест, период, общий контекст.
- **до 5–7 пунктов** (если новых статей меньше — сколько есть): `### Заголовок` → TL;DR (2–3 предложения) → ссылка на статью.
- **Вывод** (2–3 предложения): общий тренд/итог по подборке.

**Период** в заголовке и вводке бери из полей `since`/`until` ответа `search_habr`/`get_news` (формат `YYYY-MM-DD`), например «Период: <since> – <until>». **Не вычисляй и не угадывай даты сам** — у тебя нет надёжного «сегодня».

Вводку и вывод пиши **самостоятельно** на основе прочитанных статей — не копируй фрагменты из их текстов.

Тон — нейтрально-технический, русский язык. Фактологичность обязательна.

### 6. Обложка
Возьми `image` **ведущей** (первой, самой релевантной) статьи как обложку
дайджеста. Отправь обложку как фото с подписью **до 1024 символов** (заголовок дайджеста + вводка; если не умещается — обрежь по границе предложения). Тело статьи отправляй отдельным сообщением (или несколькими), разбивая по границам пунктов `###`, каждое не длиннее **4096** символов. Если у ведущей статьи нет
картинки — возьми первую доступную `image` из подборки; если ни у одной нет —
отправь статью текстом без обложки.

### 7. Запись в память (дедуп на будущее)
**Обязательный шаг — выполняй его всегда**, сразу после сборки дайджеста (шаг 5) и **независимо
от доставки**: шаг 6 (отправка в Telegram) может вообще не выполняться (например, запуск в
one-shot/CLI без Telegram) — это НЕ повод пропускать запись в память.

Вызови `mcp_mcpnews_dedup_commit(key=<ключ из шага 2>, shown_ids=SHOWN_IDS, seen_blob=SEEN_BLOB)`.
Инструмент вернёт `line` — готовую строку памяти (объединение показанного ранее с `SHOWN_IDS` и
обрезка окна сделаны в коде). Запиши `line` в память:

- если в шаге 2 строки с ключом **не было** → `memory` `add` строку `line`;
- если строка **была** → `memory` `replace`: как `old_text` передай **дословно** `SEEN_BLOB`
  (строку из шага 2), как `new_text` — `line`.

Никаких ручных операций с ID, множествами или обрезкой окна — это делает `dedup_commit`.

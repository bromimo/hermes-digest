# Навык: новостной дайджест по Хабру

Ты собираешь **связную обзорную статью-дайджест** (не просто список) на русском
языке по запросу пользователя из Telegram и присылаешь её в тот же чат.

## Инструменты

- `mcp_mcpnews_search_habr(query, period, limit)` — поиск статей по запросу,
  новейшие сверху. **Основной** инструмент для конкретной темы.
- `mcp_mcpnews_get_news(topic, period, limit)` — лента по хабу/теме из RSS.
  Запасной/широкий вариант, если поиск дал мало.
- `mcp_mcpnews_fetch_article(url)` — полный текст + метаданные + картинка
  (`image`) статьи. Зови для аннотации и для обложки.
- `memory` — встроенная память. Используется для дедупа между запросами.

`period`: `"24h"`, `"7d"`, `"30d"` или диапазон `"YYYY-MM-DD..YYYY-MM-DD"`.

## Процедура

### 1. Разбор запроса
Извлеки из сообщения **тему** и **период**. Маппинг периода:
«сегодня/за сутки/за день» → `24h`; «за неделю/последнюю неделю» → `7d`;
«за месяц» → `30d`; «за N дней» → `Nd`. Если период не указан — `7d`.

### 2. Дедуп: что уже показывали (память)
Сформируй ключ `digest:<chat_id>:<тема-slug>` (тему приведи к нижнему регистру,
пробелы → дефисы). Найди в памяти (`MEMORY.md`) строку с этим ключом и собранным
списком ID статей — это уже показанные материалы. Их нужно **исключить** из новой
выборки.

### 3. Сбор кандидатов
Вызови `search_habr(query=тема, period, limit=20)`. Если `count` мал (< 5),
дополни через `get_news(topic=тема, period, limit=10)`. Объедини, убери дубли по
URL, **выкинь уже показанные ID** из шага 2.

Если после фильтрации статей нет — вежливо сообщи пользователю по-русски, что за
указанный период новых материалов по теме не нашлось (возможно, всё уже было в
прошлых дайджестах — предложи расширить период), и заверши.

### 4. Отбор и аннотация
Отбери **5–7** самых релевантных свежих статей. Для каждой вызови
`fetch_article(url)`, чтобы получить текст и `image`. На основе текста напиши
**TL;DR в 2–3 предложения** — по сути, без воды и без выдуманных фактов
(только то, что есть в тексте/сниппете).

> Экономь вызовы: free-модель ограничена ~20 запросами/мин. Не зови
> `fetch_article` больше, чем нужно для 5–7 пунктов.

### 5. Сборка статьи
Структура (см. `templates/digest.md`):
- **Вводка** (2–3 предложения): о чём дайджест, период, общий контекст.
- **5–7 пунктов**: `### Заголовок` → TL;DR (2–3 предложения) → ссылка на статью.
- **Вывод** (2–3 предложения): общий тренд/итог по подборке.

Тон — нейтрально-технический, русский язык. Фактологичность обязательна.

### 6. Обложка
Возьми `image` **ведущей** (первой, самой релевантной) статьи как обложку
дайджеста. Отправь её в Telegram как фото с подписью = заголовок дайджеста +
вводка, затем тело статьи отдельным сообщением. Если у ведущей статьи нет
картинки — возьми первую доступную `image` из подборки; если ни у одной нет —
отправь статью текстом без обложки.

Учитывай лимит Telegram 4096 символов: при необходимости разбей на несколько
сообщений по границам пунктов.

### 7. Запись в память (дедуп на будущее)
После отправки запиши в память новые показанные ID статей под ключом
`digest:<chat_id>:<тема-slug>`. Используй `memory`:
- если строки с ключом нет — `add` строку вида
  `digest:<chat_id>:<тема-slug> ids: <id1>,<id2>,...`;
- если есть — `replace`: добавь новые ID к существующим, оставив **последние ~50**
  (старые вытесняй), чтобы не упереться в лимит памяти ~2200 символов.

ID статьи — это число из URL `https://habr.com/ru/articles/<id>/`.

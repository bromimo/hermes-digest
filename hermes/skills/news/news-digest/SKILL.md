# Навык: новостной дайджест по Хабру

Ты собираешь **связную обзорную статью-дайджест** (не просто список) на русском
языке по запросу пользователя из Telegram и присылаешь её в тот же чат.

## Инструменты

- `mcp_mcpnews_search_habr(query, period, limit)` — поиск статей по запросу,
  новейшие сверху. **Основной** инструмент для конкретной темы.
- `mcp_mcpnews_get_news(topic, period, limit)` — лента по хабу/теме из RSS.
  Запасной/широкий вариант, если поиск дал мало.
- `mcp_mcpnews_fetch_article(url)` — полный текст + метаданные + картинка
  (`image`) статьи. Зови для аннотации и для обложки.
- `memory` — встроенная память. Используется для дедупа между запросами.

`period`: `"24h"`, `"7d"`, `"30d"`, `"Nd"` (например `"3d"`) или диапазон `"YYYY-MM-DD..YYYY-MM-DD"`.

## Процедура

### 1. Разбор запроса
Извлеки из сообщения **тему** и **период**. Маппинг периода:
«сегодня/за сутки/за день» → `24h`; «за неделю/последнюю неделю» → `7d`;
«за месяц» → `30d`; «за N дней» → `Nd`. Если период не указан — `7d`.

### 2. Дедуп: что уже показывали (память)
Сформируй ключ `digest:<chat_id>:<тема-slug>` (тему приведи к нижнему регистру,
пробелы → дефисы). (`chat_id` — числовой идентификатор Telegram-чата из контекста текущего сообщения/сессии. Если определить его невозможно, используй ключ только по теме: `digest:<тема-slug>`.) Найди в памяти (`MEMORY.md`) строку с этим ключом — это **строка-снапшот** показанных ранее материалов. **Запомни её дословно**: её ID (назови их `OLD_IDS`) нужны для фильтрации (шаг 3), а сама строка — как `old_text` при записи (шаг 7). Если строки с ключом в памяти нет — `OLD_IDS` пуст.

### 3. Сбор кандидатов и фильтрация
Вызови `mcp_mcpnews_search_habr(query=тема, period, limit=20)`. Если `count` мал (< 5),
дополни через `mcp_mcpnews_get_news(topic=тема, period, limit=10)`. Объедини, убери дубли по URL.

**Фильтрация по памяти — строго механически:**
- Исключи из кандидатов **только** те статьи, чей ID **буквально присутствует** в строке-снапшоте из шага 2.
- Статью, ID которой нет в этой строке, считать **новой** — исключать её нельзя.
- Оперируй только ID, которые **дословно** встречаются в ответах инструментов или в строке памяти. **Никогда не выдумывай ID** и не объявляй показанной статью, которой нет в памяти.

Сообщение «новых материалов нет» допустимо **только** если после фильтрации не осталось **ни одного** кандидата. Если остался хотя бы один — ты **обязан** собрать дайджест из оставшихся (даже если их меньше 5–7). Если кандидатов действительно ноль — вежливо сообщи по-русски, что новых материалов за период не нашлось (предложи расширить период), и заверши.

### 4. Отбор и аннотация
Из **отфильтрованных** кандидатов (шаг 3) отбери до **5–7** самых релевантных свежих статей (если кандидатов меньше 7 — возьми все). Для каждой вызови
`mcp_mcpnews_fetch_article(url)`, чтобы получить текст и `image`. На основе текста напиши
**TL;DR в 2–3 предложения** — по сути, без воды и без выдуманных фактов
(только то, что есть в тексте/сниппете).

> Экономь вызовы: free-модель ограничена ~20 запросами/мин. Не зови
> `mcp_mcpnews_fetch_article` больше, чем нужно для 5–7 пунктов.

Если `mcp_mcpnews_fetch_article` вернул поле `error` — пропусти эту статью и возьми следующего кандидата (не прерывай дайджест).

**Зафиксируй финальный список `SHOWN_IDS`** — ID ровно тех статей, что реально войдут в итоговый дайджест (ID = число из `/articles/(\d+)/` в их `url`, уже после всех пропусков из-за `error`). Этот список — **единственный источник правды**: ровно эти статьи идут и в тело дайджеста (шаг 5), и в память (шаг 7). Никакие другие статьи (в т.ч. зафетченные, но не вошедшие в дайджест) в `SHOWN_IDS` не попадают.

### 5. Сборка статьи
Структура (см. `templates/digest.md`):
- **Вводка** (2–3 предложения): о чём дайджест, период, общий контекст.
- **до 5–7 пунктов** (если новых статей меньше — сколько есть): `### Заголовок` → TL;DR (2–3 предложения) → ссылка на статью.
- **Вывод** (2–3 предложения): общий тренд/итог по подборке.

**Период** в заголовке и вводке бери из полей `since`/`until` ответа `search_habr`/`get_news` (формат `YYYY-MM-DD`), например «Период: <since> – <until>». **Не вычисляй и не угадывай даты сам** — у тебя нет надёжного «сегодня».

Вводку и вывод пиши **самостоятельно** на основе прочитанных статей — не копируй фрагменты из их текстов.

Тон — нейтрально-технический, русский язык. Фактологичность обязательна.

### 6. Обложка
Возьми `image` **ведущей** (первой, самой релевантной) статьи как обложку
дайджеста. Отправь обложку как фото с подписью **до 1024 символов** (заголовок дайджеста + вводка; если не умещается — обрежь по границе предложения). Тело статьи отправляй отдельным сообщением (или несколькими), разбивая по границам пунктов `###`, каждое не длиннее **4096** символов. Если у ведущей статьи нет
картинки — возьми первую доступную `image` из подборки; если ни у одной нет —
отправь статью текстом без обложки.

### 7. Запись в память (дедуп на будущее)
**Обязательный шаг — выполняй его всегда**, сразу после сборки дайджеста (шаг 5) и **независимо от доставки**: шаг 6 (отправка в Telegram) может вообще не выполняться (например, запуск в one-shot/CLI без Telegram) — это НЕ повод пропускать запись в память. Обнови строку памяти под ключом из шага 2. В память пиши **только** ID из `SHOWN_IDS` (статьи, реально вошедшие в дайджест) — ничего выдуманного и никаких непоказанных кандидатов.

- `OLD_IDS` — ID из строки-снапшота шага 2 (если строки не было — пусто).
- `NEW_IDS` = `OLD_IDS` ∪ `SHOWN_IDS`; оставь только **последние ~50** (самые старые слева отбрось), чтобы не превысить лимит памяти ~2200 символов.
- Если строки в снапшоте шага 2 **не было** → `memory` `add` строку: `digest:<chat_id>:<тема-slug> ids: <NEW_IDS>`.
- Если строка **была** → `memory` `replace`: как `old_text` передай **дословно строку-снапшот** из шага 2, как `new_text` — `digest:<chat_id>:<тема-slug> ids: <NEW_IDS>`.

ID статьи — число из `/articles/(\d+)/` в её `url`. В память кладём ТОЛЬКО числа, не полные URL.
